文档站搜索框设计

背景​

当前站点基于 Docusaurus 3 构建，顶部导航包含文档入口和若干自定义页面。本站需要新增一个搜索框，用于检索 docs/ 下的文档内容，不覆盖 src/pages 中的产品对比、工具等自定义页面。

目标​

  • 在站点导航区域提供可直接使用的搜索入口
  • 搜索范围仅限 docs/ 文档内容
  • 保持现有中文文档结构和路由不变
  • 优先使用成熟插件，避免自定义搜索实现

非目标​

  • 不接入 Algolia DocSearch
  • 不为 src/pages 自定义页面建立索引
  • 不新增独立搜索结果页或自定义搜索后端

方案选择​

采用 @easyops-cn/docusaurus-search-local 本地搜索插件。

选择原因：

  • 与当前 Docusaurus 项目集成成本低
  • 无需依赖外部搜索服务
  • 适合中文文档站的自托管场景
  • 可以通过配置将索引范围限制在文档内容

实现设计​

依赖​

在项目中添加 @easyops-cn/docusaurus-search-local 依赖。

配置​

在 docusaurus.config.ts 中注册本地搜索插件，并配置：

  • 启用搜索栏 UI
  • 仅索引文档内容
  • 不索引博客
  • 不索引页面
  • 保持中文站点可用的基础分词配置

界面​

搜索框使用插件默认注入到导航栏的交互形式，避免额外 swizzle 或自定义主题改造，先以稳定接入为主。

验收标准​

  • 页面顶部可见并可用的搜索入口
  • 输入文档关键字后可返回 docs/ 内容结果
  • 搜索结果不包含产品对比、工具等自定义页面
  • 本地开发和生产构建均可通过

风险与取舍​

  • 本地搜索索引会增加部分构建产物体积，但对当前站点规模可接受
  • 默认搜索 UI 可定制性有限，但能显著降低维护成本
  • 中文搜索效果依赖插件分词策略，首版以“可用且稳定”为优先
