VoidModule Debug - VoidDebug UART Mini

1. 简介​

VoidDebug UART Mini 是一款面向嵌入式调试与联调场景的 Debug 模块，采用 CH340K 方案，用于实现 USB 与 TTL UART 之间的串口桥接。

该模块适合用于 MCU 下载辅助、串口日志输出、AT 模块调试、外设联调和基础通信实验。板上集成 RT9193-33 稳压器以及 DTR / RTS -> RST / BOOT 自动控制电路，更适合做带自动下载的最小调试接口。

信息

本文参数综合自当前 V1.0 原理图、PCB 丝印和 WCH 官方 USB 转 UART 选型表。板级电压和引脚定义以仓库内原理图为准，芯片级能力以 WCH 官方资料为准。

2. 核心特点​

  1. 核心方案：CH340K
  2. 接口类型：USB 转 TTL UART
  3. 模块供电：5 V USB 输入
  4. 逻辑电平：板载 UART 默认 3.3 V
  5. 默认配置：+5V / VCC(3.3V) / TXD / RXD / CTS / RST / BOOT / GND
  6. 典型用途：串口下载 / 日志输出 / 模块联调 / 自动下载辅助

4.2 引脚注意事项​

  1. TXD 与目标设备 RX 相连，RXD 与目标设备 TX 相连。
  2. 模块与目标板必须 共地，否则容易出现乱码、无响应或枚举正常但通信失败。
  3. 本板的 UART 信号链路按 3.3 V 逻辑实现，目标板若为 5 V 串口系统，不建议直接相连。
  4. RST 与 BOOT 为板载自动下载控制输出，不是普通串口数据引脚。
警告

USB 转串口模块最常见的问题不是驱动，而是 电平不匹配 和 没有共地。本模块板载 CH340K 由 3.3 V 供电，适合直接对接 3.3 V MCU；若目标系统不是 3.3 V 逻辑，请先做电平匹配。

6.2 接线建议​

  1. 初次调试时先只接 GND / TXD / RXD 三根线。
  2. 若目标板已独立供电，先不要额外连接模块的 +5V / VCC。
  3. 需要自动下载时，再补接 RST / BOOT。
  4. 若出现乱码，先确认波特率、时钟配置和逻辑电平，再排查驱动问题。
提示

串口模块联调时，优先遵循“先共地、再交叉 TX/RX、最后确认供电”的顺序，通常能更快定位问题。

7.2 最小通信流程​

  1. 将模块插入电脑，确认系统已识别出串口设备。
  2. 按接线表连接 GND / TXD / RXD。
  3. 打开串口工具，设置为 115200 8N1。
  4. 让目标板输出固定字符串，如 hello。
  5. 确认电脑侧可稳定接收，再继续做回传或下载控制。

8. 快速上手​

8.1 你需要准备​

  1. VoidDebug UART Mini 模块
  2. 一块带 UART 的目标开发板
  3. 一根支持数据通信的 USB 线
  4. 串口终端工具或下载工具

8.2 最小验证步骤​

  1. 将模块连接电脑，确认串口设备出现。
  2. 将 GND / TXD / RXD 与目标板正确连接。
  3. 在目标板固件中输出串口日志。
  4. 打开串口工具并选择正确端口和波特率。
  5. 观察日志输出是否连续、无乱码、无丢字。

10. 注意事项​

  1. 先确认目标系统的串口逻辑电平，再连接 TXD / RXD。
  2. TXD 与 RXD 必须交叉连接，不能同名直连。
  3. 不确定供电关系时，优先只接信号线和地线，不额外接 +5V / VCC。
  4. 若电脑能识别串口但没有数据，优先检查接线和波特率，而不是先怀疑芯片损坏。
  5. 本模块引出了 RST / BOOT，适合与支持自动下载的目标板配合使用。

11. 常见问题​

电脑已经识别串口，但没有任何输出，怎么排查？
  1. 检查 TXD / RXD 是否接反。
  2. 检查是否与目标板共地。
  3. 检查波特率、校验位、停止位是否一致。
  4. 检查目标板程序是否真的在对应 UART 输出日志。
出现乱码，通常是什么原因？
  1. 波特率配置不一致。
  2. MCU 时钟配置错误。
  3. 串口逻辑电平不匹配。
  4. 接线过长或接触不良。
模块能给目标板供电吗？

可以，但不建议在未确认板卡电源路径、电流需求和反灌风险前直接这样做。初次联调更推荐目标板独立供电，USB 转串口模块只负责 GND / TXD / RXD 通信链路。
