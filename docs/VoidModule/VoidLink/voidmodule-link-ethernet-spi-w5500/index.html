VoidModule Link - Ethernet SPI W5500

1. 简介​

Ethernet SPI W5500 是一款面向嵌入式主控板的 Link 通信模块，采用 W5500 方案，通信接口为 SPI。

该模块适合用于 MCU 以太网接入、局域网通信实验、网络状态显示与联网控制等场景。文档以模块实物接入、接口使用和工程集成为重点，不以芯片手册翻译为目标。

信息

当前页面主要依据模块实物图和你提供的原理图整理。已确认模块采用 W5500 + 25 MHz 晶振 + 带变压器 RJ45 结构，板上引出了 VCC / GND / SCK / MISO / MOSI / CS / INT / RST 接口。

2. 核心特点​

  1. 核心方案：W5500
  2. 接口类型：SPI
  3. 模块供电：3.3 V（不支持 5 V 输入）
  4. 逻辑电平：3.3 V
  5. 默认配置：SPI 以太网控制器 / 25 MHz 晶振 / RJ45 带指示灯
  6. 外形尺寸：待补充

4.2 引脚注意事项​

  1. 本模块按 3.3 V 供电和逻辑设计，不支持 5 V 输入。
  2. CS 必须由主控 GPIO 独立控制，不建议悬空或长期固定低电平。
  3. RST 建议接入 MCU GPIO，便于上电初始化和异常恢复。
警告

模块原理图中未看到电平转换器和板载 3.3 V 稳压器，请按 3.3 V 供电并使用 3.3 V 逻辑主控；模块 不支持 5 V 供电输入，若主控为 5 V 系统，信号侧也需增加电平转换。

6.2 接线建议​

  1. 初次调试建议先连接 VCC / GND / SCK / MISO / MOSI / CS / RST，INT 可后接。
  2. SPI 连线尽量短，GND 要可靠共地，避免长线悬空造成通信不稳。
  3. 若网络链路不稳定，优先排查电源完整性、RJ45 焊接和 SPI 时钟设置。
提示

第一次联调时建议先不使用中断，采用轮询方式验证 SPI 通信 + 芯片识别 + MAC/IP 配置，确认基本联网能力后再接入 INT 做事件驱动。

7. 通信说明 / 控制方法​

7.1 接口配置​

数据位宽8 bit常规 MCU SPI 配置
时序/模式待补充以实际驱动配置和 W5500 数据手册为准

7.2 控制流程建议​

  1. 上电后先保持 RST 有效复位。
  2. 拉高 RST，等待芯片稳定。
  3. 通过 SPI 读取版本寄存器或关键寄存器，确认通信正常。
  4. 配置 MAC、IP、Gateway、Subnet 等网络参数。
  5. 根据应用选择 TCP / UDP / DHCP / 静态 IP 初始化流程。

8. 快速上手​

8.1 你需要准备​

  1. Ethernet SPI W5500 模块
  2. 具备 3.3 V SPI 的主控板
  3. 网线与交换机 / 路由器 / 直连测试环境
  4. 可编译的 W5500 驱动工程

8.2 最小验证步骤​

  1. 按接线表连接 VCC、GND、SCK、MISO、MOSI、CS、RST。
  2. 上电后通过 SPI 读取 W5500 寄存器，确认芯片在线。
  3. 配置固定 MAC 与静态 IP。
  4. 连接网线后测试 Ping。
  5. 再继续验证 TCP Server / TCP Client / UDP 功能。

10. 注意事项​

  1. 本模块按 3.3 V 系统设计，供电和逻辑都应按 3.3 V 处理，不支持 5 V 输入。
  2. INT 引脚可选接入，不影响最基础的联网验证。
  3. RST 建议接入主控，以便掉线或异常时快速恢复。
  4. 若使用较长 SPI 连线，建议降低时钟并优先验证寄存器读写稳定性。
  5. W5500 仅负责以太网控制，不替代主控侧应用协议逻辑。

11. 常见问题​

模块完全无法联网，如何排查？
  1. 检查 VCC / GND 是否正确且稳定。
  2. 检查网口指示灯是否有链路变化。
  3. 检查 RST 是否正确释放。
  4. 检查主控是否能正确读写 W5500 寄存器。
SPI 能通信，但 Ping 不通，可能是什么原因？
  1. MAC / IP / Gateway / Subnet 参数配置错误。
  2. 网线或交换机环境异常。
  3. Socket 初始化流程不完整。
  4. 模块未正确建立物理链路。
需要接 INT 吗？

不是必须。最小验证阶段可以先不接 INT，通过轮询方式完成初始化和数据收发；后续若需要更高效的事件处理，再接入中断。
