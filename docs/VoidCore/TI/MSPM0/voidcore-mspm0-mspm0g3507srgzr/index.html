VoidCore MSPM0 – MSPM0G3507SRGZR

基于 MSPM0G3507SRGZR 的混合信号开发板

一块基于 MSPM0G3507SRGZR（Arm Cortex-M0+，80 MHz）的混合信号开发板。
采用 USB Type-C 供电，板载 CH340N USB 转串口，并引出 +5V / GND / RST / SWCLK / SWDIO 五线调试接口。
适合用于 ADC / DAC / COMP / OPA、PWM 控制、串口通信和 CAN-FD 相关实验。

1 特性一览​

特性说明
核心芯片MSPM0G3507SRGZR（Arm Cortex-M0+，最高 80 MHz）
Flash / RAM128 KB / 32 KB
封装48-pin VQFN（RGZ，7 mm × 7 mm）
供电方式USB Type-C 5 V 输入，板载 RT9193-33GB 输出 3.3 V
调试接口五线调试接口（+5V、GND、RST、SWCLK、SWDIO）
板载串口CH340N USB 转 UART
板载交互BOOT0 按键、RST 复位按键、电源指示灯
可用 GPIO芯片级最多 44 GPIO，板上已引出大量 PAx / PBx
通信外设4 × UART、2 × I2C、2 × SPI、1 × CAN-FD
模拟外设2 × 12-bit 4 Msps ADC、1 × 12-bit DAC、3 × COMP、2 × OPA、1 × GPAMP
定时器7 组定时器，最多支持 22 路 PWM
特色模拟资源丰富、支持 CAN-FD、适合采样控制与混合信号实验
这块板适合做什么
  • ADC、比较器、DAC、片上运放等混合信号实验
  • GPIO、PWM、UART、I2C、SPI、CAN-FD 基础与进阶验证
  • 传感器采集、执行器驱动、小型控制板原型
  • 从 8 位单片机迁移到 32 位 MCU，同时保留较强模拟能力
不建议用于
  • 直接驱动 CAN 总线而不外接收发器的场景
  • 未确认参考电压和模拟接地就直接做高精度采样的场景
  • 高功率负载直接挂接、缺少隔离或保护的实验

2.2 引脚定义​

关于引脚编号

MSPM0G3507SRGZR 使用 48-pin RGZ (VQFN) 封装。
板卡丝印中的 Axx / Bxx 对应芯片 GPIO 名称 PAxx / PBxx，便于直接按丝印接线。
完整引脚复用与外设映射请以 TI 数据手册和技术参考手册为准。

引脚功能说明
PA19SWDIO五线调试接口 DIO
PA20SWCLK五线调试接口 CLK
NRST硬件复位调试接口 RST，同时接复位按键
PA10 / PA11UART 相关引脚默认连接板载 CH340N
PA18A1_3 / BOOT0与板载 BOOT0 按键复用
PA23VREF+外部参考电压输入
PA21VREF- / A1_7模拟参考相关引脚
PA27 ~ PA24A0_0 ~ A0_3常用 ADC0 模拟输入
PA18 ~ PA15A1_3 ~ A1_0常用 ADC1 模拟输入
PB17 ~ PB20扩展模拟 / 定时器资源适合继续做采样与控制扩展

调试与引脚复用注意事项
  • PA19 / PA20 默认用于调试，程序稳定前不要复用为普通 GPIO。
  • PA10 / PA11 已被板载 CH340N 占用，做串口调试时建议优先沿用这组引脚。
  • PA18 同时连接板载 BOOT0 按键，作为 ADC 或普通 IO 使用时要确认按键电路不会干扰。
  • PA23 (VREF+)、PA21 (VREF-) 与 A0_x / A1_x 等模拟引脚接线时，要特别注意参考电压与输入范围。
  • MSPM0G3507 片上提供 CAN-FD 控制器，如需接入实际总线，仍需外接 CAN 收发器。

4 快速上手​

你需要准备
  • USB 数据线 × 1
  • SWD 调试器 × 1（推荐 XDS110、CMSIS-DAP 或 J-Link）
  • 杜邦线 若干
  • 电脑（Windows / macOS / Linux）

4.1 安装开发环境​

  • Code Composer Studio（推荐）
  • Keil MDK
  • 其他工具链
  1. 前往 TI 官网 下载并安装 Code Composer Studio。
  2. 首次启动后选择一个 Workspace 文件夹。
  3. 通过 Resource Explorer 或 MSPM0 SDK 导入示例工程。
  4. 创建或导入工程时选择目标器件 MSPM0G3507。
  5. 如需图形化配置，可配合 SysConfig 使用。
  1. 安装 Keil MDK。
  2. 通过 Pack Installer 安装 TI MSPM0 对应器件支持包。
  3. 新建工程时选择 MSPM0G3507 对应器件。
  4. 将调试器配置为 CMSIS-DAP 或 J-Link 后即可下载调试。
  1. 如使用 TI ARM Clang 或 GCC 工具链，建议基于 MSPM0 SDK 工程模板起步。
  2. 初期先确保 GPIO 点灯 + SWD 下载 跑通，再逐步接入 ADC、I2C、SPI 或 CAN-FD。

4.2 接线​

板右侧已经给出标准五线调试接口，可按下表连接：

调试器                  开发板调试接口
─────────────          ──────────────
+5V     ────────────── +5V（可选，若板子已用 USB-C 供电可不接）
GND     ────────────── GND
RST     ────────────── RST
SWCLK   ────────────── CLK（PA20）
SWDIO   ────────────── DIO（PA19）
注意事项
  1. 推荐优先使用板载 USB-C 给板子供电，再把调试器作为纯调试接口接入。
  2. RST 最好一起接上，下载和恢复连接会更稳。
  3. 如果连不上芯片，先确认 PA19 / PA20 没有被程序错误复用。
  4. 连接异常时可尝试降低 SWD 频率，或使用调试器的 Connect Under Reset。

4.3 串口驱动与首次上电检查​

  1. 连接 USB-C 后先看 PWR 指示灯是否点亮。
  2. 用万用表测量 VCC 与 GND 之间是否为稳定 3.3 V。
  3. 板载 CH340N 连接到 PA10 / PA11，可作为默认串口调试通道。
  4. 若板子无法启动，先排查 USB 线、供电芯片和是否有焊接短路。
  5. 若需要恢复程序，可尝试按住 RST 或结合连接到 PA18 的 BOOT0 按键进行引导测试。
  • Windows
  • macOS
  • Linux

推荐安装 CCS 和对应调试器驱动后通过 SWD 下载。
如需串口日志，安装 CH340 驱动后在设备管理器中查看 USB-SERIAL CH340 对应的 COM 口即可。

macOS 下一般直接使用 J-Link 或 CMSIS-DAP 进行下载。
如需串口日志，可安装 CH340 驱动后使用 ls /dev/tty.* 或 ls /dev/cu.* 检查设备。

Linux 下建议先确认调试器是否被识别，再通过 CCS 或命令行工具下载。
CH340N 一般会识别成 /dev/ttyUSB0 一类设备，必要时可将当前用户加入 dialout 组。

4.4 烧录验证​

  1. 给开发板接入 USB-C 电源，再连接调试器。
  2. 在 CCS 中导入一个最小示例，例如 GPIO 翻转或定时器中断。
  3. 编译并下载程序，确认调试器能稳定识别 MSPM0G3507。
  4. 可优先选择一根已经引出的 IO 做点灯、方波输出或 ADC 采样验证。
  5. 若同时验证串口，建议把日志输出到 PA10 / PA11 对应 UART，方便通过 CH340N 直接查看。

7 常见问题​

Q1：烧录时无法连接目标芯片怎么办？​

  1. 检查 USB-C 是否正常供电，PWR 灯是否亮。
  2. 确认 +5V / GND / RST / CLK / DIO 连接无误。
  3. 确认程序没有把 PA19 / PA20 改作普通 GPIO。
  4. 降低 SWD 频率，或尝试 Connect Under Reset。

Q2：ADC 采样值跳动大或明显不准怎么办？​

  1. 先确认输入电压没有超出 0 ~ VDD 范围。
  2. 检查 VREF+ / VREF- 的接线和参考源配置。
  3. 模拟输入不要和高频 PWM、SPI 时钟线并排乱飞线。
  4. 适当增加采样时间，并对输入做 RC 滤波或软件平均。

Q3：为什么 CAN-FD 连不上总线？​

  1. MSPM0G3507 片上提供的是 CAN 控制器，不是总线收发器。
  2. 外接 CANH / CANL 前需要增加独立 CAN Transceiver。
  3. 确认位时序、终端电阻和收发器供电都正确。

Q4：如果把调试引脚占用了，还有办法救回来吗？​

  1. 优先尝试 Connect Under Reset 重新接管芯片。
  2. 芯片默认支持 BSL，引脚 PA0 / PA1 可作为默认 I2C Bootloader 通道。
  3. 实在不行时，建议回到最小连接，把供电、RST 和调试线重新单独拉线排查。
