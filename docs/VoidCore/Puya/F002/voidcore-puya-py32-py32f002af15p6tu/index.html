VoidCore PY32 – PY32F002AF15P6TU

基于 PY32F002AF15P6TU 的入门开发板

一块基于 PY32F002AF15P6TU 的小型入门开发板。
采用 USB Type-C 供电，板载 CH340N USB 转串口、RT9193-GB33 3.3 V LDO，并保留 BOOT0 / RST 双按键 与 DIO / CLK / RST / GND 调试接口。
板上同时引出多组 A / B / F 口引脚，适合做基础 GPIO、串口、定时器和最小系统原型验证。

当前文档说明

这页已按 STM32F070F6P6 的文档结构重排。
当前内容主要依据你给的板卡正面图与丝印整理；芯片详细资源数量、电气极限和完整复用功能，建议后续再结合数据手册补齐。

2.3 板载资源映射​

资源连接引脚备注
Type-C 输入+5V板载主供电输入，CC 端各有 5.1kΩ 电阻

USB 转串口CH340NRXD -> PA2，TXD -> PA3，用于板载串口通信

RST 按键RST板载硬件复位
调试接口 DIODIO调试数据线

调试接口 RSTRST调试复位线
调试接口 GNDGND调试与系统共地
电源指示灯PWR接在 VCC 电源轨，上电常亮
VCC 排针VCC板载 3.3 V 工作电压引出

根据原理图，芯片主要引脚引出关系如下：

  • PA13-SWD：调试数据
  • PA14-SWC：调试时钟
  • PF2-NRST：复位
  • PB6/PF4-BOOT0：启动模式相关
  • PA2 / PA3：与 CH340N 相连，用于 USART1
  • PF0-OSCIN / PF1-OSCOUT：外部时钟相关引脚已引出
调试与复用注意事项
  • BOOT0 会影响启动方式，下载和正常运行时要区分按键状态。
  • 板载 USB 转串口与 USART1 相关，复用引脚前要先确认工程目标。
  • DIO / CLK / RST 建议在开发初期优先保留给调试链路。
  • 若同时从 Type-C 和外部调试工具供电，请先确认是否存在重复供电风险。

2.4 原理图​

4 快速上手​

你需要准备
  • USB Type-C 数据线 × 1
  • 调试 / 下载工具 × 1
  • 杜邦线 若干
  • 电脑（Windows / macOS / Linux）

4.1 安装开发环境​

  • 推荐流程
  • 其他工具链
  1. 安装对应的芯片支持包、编译工具链与下载工具。
  2. 创建或导入 PY32F002AF15P6TU 对应工程。
  3. 先确认板载串口和下载器至少有一条链路可用。
  4. 初次建议从点灯或串口打印工程开始。
  1. 如使用第三方 IDE 或构建系统，先确认其支持目标芯片。
  2. 优先验证 GPIO + UART + 下载 这三件事，再扩展到更多外设。
  3. 复杂工程开发前，建议先留住调试口，避免把自己锁死在程序里。

4.2 接线​

本开发板已引出四线调试接口，可按下表连接：

调试器                    开发板调试接口
─────────────            ──────────────
DIO          ───────────  DIO
CLK          ───────────  CLK
RST          ───────────  RST
GND          ───────────  GND

右侧旁边还保留 +5V 焊盘，可作为电压参考或外部供电连接点使用。

注意事项
  1. 若板子已通过 Type-C 供电，外接工具时要避免重复供电。
  2. 初次调试建议保留 RST 连接，下载失败时更容易排查。
  3. 如果程序占用了 USART1 相关引脚，串口日志可能会失效。
  4. PA2 / PA3 已与 CH340N 相连，若改作其他功能要同时考虑板载串口影响。

本板带有 CH340N 板载 USB 转串口电路，连接电脑后建议先确认串口是否正常枚举。

7 常见问题​

Q1：为什么上电正常，但串口没有输出？
  1. 先确认电脑是否识别出串口设备。
  2. 检查程序是否仍使用 USART1 作为日志输出。
  3. 检查对应引脚是否被复用到其他功能。
  4. 必要时用最小串口打印工程重新验证。
Q2：下载失败怎么办？
  1. 检查 DIO / CLK / RST / GND 接线是否正确。
  2. 检查供电是否稳定。
  3. 确认 BOOT0 状态没有影响当前启动方式。
  4. 必要时断开外接模块，仅保留最小系统重试。
Q3：这块板更适合先学什么？

建议先完成 GPIO、按键、中断、串口打印，再继续到 PWM、ADC 和更复杂的应用。
