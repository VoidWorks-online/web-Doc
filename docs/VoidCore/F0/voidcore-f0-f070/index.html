VoidCore F0 – F070

基于 STM32F070F6P6 的开发板

一块基于 STM32F070F6P6（Cortex-M0, 48 MHz）的自制学习开发板。
Type-C 接口供电，板载 CH340 USB 转串口，引出 SWD 调试接口，插上线就能烧录。
仅 20 个引脚的超紧凑封装，自带 USB 2.0 Full-Speed 外设，非常适合入门学习。

1 特性一览​

特性说明
核心芯片STM32F070F6P6（Arm Cortex-M0，48 MHz）
Flash / RAM32 KB / 6 KB
封装TSSOP-20（6.4 × 4.4 mm）
供电方式USB Type-C（5 V），板载 3.3 V LDO
调试接口SWD（支持 ST-Link / DAP-Link / J-Link）
板载串口CH340 USB 转 UART，免跳线直连 PC
可用 GPIO最多 15 个（含复用功能）
通信外设2× USART、1× I²C、1× SPI、1× USB 2.0 FS
模拟外设12-bit ADC（最多 9 个外部通道）
定时器TIM1、TIM3、TIM14、TIM16、TIM17、TIM6、TIM7、IWDG、WWDG、RTC
与 STM32G031G8U6 的主要区别
  • 内核：F070 为 Cortex-M0（48 MHz），G031 为 Cortex-M0+（64 MHz，更高效）
  • 存储：F070 为 32 KB Flash / 6 KB RAM，G031 为 64 KB / 8 KB
  • USB：F070 自带原生 USB 2.0 Full-Speed 外设，G031 无 USB
  • 封装：F070 为 TSSOP-20（20 脚），G031 为 UFQFPN-28（28 脚，GPIO 更多）
  • 供电范围：F070 为 2.4–3.6 V，G031 为 1.7–3.6 V

2.2 引脚定义​

关于引脚编号

STM32F070F6P6 采用 TSSOP-20 封装，共 20 个引脚。
由于引脚数量有限，部分引脚存在多 GPIO 共用同一物理引脚的情况（如 Pin 17 同时对应 PA9/PA11，Pin 18 对应 PA10/PA12），可通过 SYSCFG 寄存器进行重映射选择。

TSSOP-20 完整引脚表​

引脚号引脚名类型主要复用功能（常用）
1BOOT0I启动模式选择（高电平 = 从系统存储器启动）
2PF0I/OOSC_IN（外部 HSE 晶振输入）
3PF1I/OOSC_OUT（外部 HSE 晶振输出）
4NRSTI/O复位（低电平有效）
5VDDAS模拟电源 3.3 V
6PA0I/OUSART1_CTS / ADC_IN0 / TIM1_CH1
7PA1I/OUSART1_RTS / ADC_IN1 / TIM1_CH2
8PA2I/OUSART1_TX / ADC_IN2 / TIM1_CH3
9PA3I/OUSART1_RX / ADC_IN3 / TIM1_CH4
10PA4I/OSPI1_NSS / ADC_IN4 / TIM14_CH1 / USART1_CK
11PA5I/OSPI1_SCK / ADC_IN5
12PA6I/OSPI1_MISO / ADC_IN6 / TIM3_CH1 / TIM16_CH1

S = 电源引脚，I/O = 通用输入/输出，I = 仅输入。
Pin 17/18 的 PA9↔PA11、PA10↔PA12 重映射通过 SYSCFG_CFGR1 寄存器控制。
完整复用功能映射请参考 ST 官方 Datasheet。

2.3 板载资源映射​

资源连接引脚备注
CH340 USB-UART TXPA9（USART1_TX）通过 CH340 转 USB Type-C，连接电脑即出现 COM 口
CH340 USB-UART RXPA10（USART1_RX）同上
SWD_IOPA13调试专用，勿随意复用为 GPIO
SWD_CLKPA14调试专用，勿随意复用为 GPIO
NRSTPin 4复位引脚，SWD 调试器可选连接
BOOT0Pin 1默认接 GND（从 Flash 启动），跳线接 3.3 V 可进入 Bootloader
Type-C 5 V 输入—经板载 LDO 降压至 3.3 V 供给 MCU
PA9/PA10 与 USB 的引脚冲突

在 TSSOP-20 封装中，PA9/PA11 和 PA10/PA12 分别共用 Pin 17 和 Pin 18。由于板载 CH340 已占用 PA9/PA10（USART1），如需使用芯片原生 USB 功能，需要通过 SYSCFG_CFGR1 将 Pin 17/18 重映射为 PA11/PA12（USB_DM/DP），并且此时串口不可用。

4 快速上手​

你需要准备
  • USB Type-C 数据线 × 1（注意要数据线，不要只能充电的线）
  • SWD 调试器 × 1（ST-Link V2 / DAP-Link / J-Link 任选其一）
  • 杜邦线 若干（连接调试器与开发板）
  • 电脑（Windows / macOS / Linux）

4.1 安装开发环境​

  • STM32CubeIDE（推荐）
  • Keil MDK
  • PlatformIO + VS Code
  1. 前往 ST 官网 下载 STM32CubeIDE（免费，全平台支持）。
  2. 安装完成后首次启动，选择一个 Workspace 文件夹。
  3. 菜单 File → New → STM32 Project，在芯片选择器中搜索 STM32F070F6P6，选中后点击 Next。
  4. 填写项目名称，Targeted Language 选 C，Firmware Package 选最新版本，完成创建。
  5. ST-Link 驱动通常随 CubeIDE 自动安装。如果设备管理器识别不到，可手动安装 STSW-LINK009。
  1. 下载并安装 Keil MDK（Community 版免费，限制 32 KB 代码——刚好覆盖 F070F6 的 32 KB Flash）。
  2. 打开 Pack Installer，搜索 STM32F0，安装 Keil.STM32F0xx_DFP 包。
  3. 新建项目时 Device 选择 STM32F070F6Px。
  4. 安装 ST-Link 驱动：STSW-LINK009。
  1. 安装 VS Code，在扩展商店搜索 PlatformIO IDE 并安装。
  2. 新建项目，Board 选择 genericSTM32F070F6，Framework 选 stm32cube。
  3. PlatformIO 会自动下载对应的 HAL 库和工具链。

4.2 接线​

只需要连接 3 根线（推荐 4 根）：

调试器 (ST-Link)          开发板 SWD 排针
─────────────            ──────────────
3.3V  ────────────────── 3V3  （可选，板子 Type-C 自带供电）
GND   ────────────────── GND
SWDIO ────────────────── SWDIO (PA13)
SWCLK ────────────────── SWCLK (PA14)
注意事项
  1. 调试器输出电压可以使用 3.3 V 或者 5 V。
  2. 烧录时需要同时用 Type-C 数据线供电（CH340 需要 USB 5 V），调试器的 3.3 V 只是信号参考，不建议单独作为板子电源。
  3. 如果连接了 NRST，调试器可以自动复位芯片；未连接时在 IDE 中选择 Software Reset 即可。
  4. 禁止 ST-Link 在 +3.3 V 供电的同时接入 Type-C，可能会烧毁 ST-Link。
  5. 确认 BOOT0（Pin 1）接 GND 或悬空（默认从 Flash 启动）。如果 BOOT0 意外接高，芯片会进入 Bootloader 而非运行用户程序。

4.3 安装 CH340 驱动​

首次将 Type-C 线连接电脑后，系统需要识别板载 CH340 芯片：

  • Windows
  • macOS
  • Linux

大多数 Windows 10/11 系统会自动安装驱动。如果设备管理器中出现黄色感叹号，手动下载安装：CH340 驱动（南京沁恒官网）。安装后在「设备管理器 → 端口」中看到 USB-SERIAL CH340 (COMx) 即为成功。

macOS 需要手动安装驱动：CH340 macOS 驱动。安装后在终端执行 ls /dev/tty.wchusbserial* 确认设备出现。

Linux 内核自带 ch341 驱动，插入后执行 dmesg | tail 即可看到类似 /dev/ttyUSB0 的设备。如果权限不够，执行：

sudo usermod -aG dialout $USER

然后重新登录。

4.4 烧录验证​

克隆示例代码仓库后，打开第一个例程工程，编译并烧录到开发板。按照例程的接线说明连接 LED，看到 LED 闪烁即表示环境搭建成功。

随后可打开串口工具（推荐 Vofa+ 或 SSCOM），选择 CH340 对应的 COM 口，波特率 115200，验证串口通信是否正常。

6 工程结构说明​

每个例程为独立的 STM32CubeIDE / Keil 工程，目录结构如下：

ExNN_模块_功能/
├── Core/Inc/          ── 头文件（main.h, mpu6050.h 等）
├── Core/Src/          ── 源文件（main.c, mpu6050.c 等）
├── Drivers/           ── HAL 库驱动（STM32CubeMX 生成）
├── README.md          ── 例程说明文档
└── .ioc               ── CubeMX 工程配置文件

所有用户代码均写在 CubeMX 的 USER CODE BEGIN / END 区域内，方便重新生成外设配置而不丢失代码。

7 学习路径建议​

推荐进度

建议按阶段顺序完成例程，每个例程预计 1–3 课时（45 分钟/课时）。

  • 第一阶段（例程 01–08）：1–2 周，打好外设基础
  • 第二阶段（例程 09–13）：1 周，掌握通信协议
  • 第三阶段（例程 14–17）：1–2 周，学习数据处理与算法
  • 第四阶段（例程 18–20）：1 周，完成综合项目

总计约 4–6 周 可完成全部例程。

完成基础例程后，鼓励尝试自行组合功能进行扩展，比如将 PWM + ADC 结合实现「旋钮调光」，或在计步器基础上增加 OLED 显示等。

8 常见问题​

烧录时提示 "No target connected" 或 "Error connecting to target"
  1. 检查 SWD 线（尤其 GND）是否接牢。
  2. 确认调试器驱动已安装——在设备管理器中应能看到 ST-Link 设备。
  3. 确认 Type-C 已插入且板子有供电（用万用表量 3.3 V 是否正常）。
  4. 在 IDE 的调试器设置中尝试降低 SWD 频率（如从 4 MHz 降到 480 kHz）。
  5. 如果芯片之前被错误配置了 PA13/PA14 为 GPIO，可以尝试按住 NRST 再点烧录，在松手的瞬间连接。
  6. 确认 BOOT0 引脚是否悬空或接 GND，若被拉高会进入 Bootloader 而非 Flash 启动。
串口没有输出 / 收到乱码
  1. 确认波特率两端一致——代码设置 115200，串口工具也要设为 115200。
  2. 在设备管理器中确认 CH340 驱动正常，记下正确的 COM 口号。
  3. F070 使用内部 8 MHz HSI + PLL 倍频到 48 MHz，如果 PLL 配置有误，实际波特率会偏离导致乱码。
  4. 检查代码中 USART1 的引脚映射——F070F6 的 TSSOP-20 封装中 USART1_TX/RX 在 PA9/PA10（Pin 17/18）。
ADC 读数不准或一直为 0
  1. F070 的 ADC 使用前建议执行自校准。
  2. 确认引脚配置为模拟输入模式，没有使能内部上拉/下拉。
  3. 确认 VDDA 引脚（Pin 5）供电正常（必须 ≥ 2.4 V）。
  4. 用万用表测量引脚实际电压，确认硬件连接正常。
如何判断 Type-C 线是数据线还是充电线？

插上电脑后如果设备管理器中没有出现任何新设备（包括 CH340），而板子有供电，说明可能是只能充电的线。换一根线试试——通常两头都有 USB 标志的更可能是数据线。

想使用原生 USB 功能，但 CH340 占用了 Pin 17/18

F070F6P6 的 TSSOP-20 封装中，Pin 17 同时对应 PA9 和 PA11，Pin 18 对应 PA10 和 PA12。默认为 PA9/PA10（USART1，接 CH340）。要使用 USB（PA11=DM, PA12=DP），需要在代码中通过 SYSCFG_CFGR1 寄存器将引脚重映射为 PA11/PA12，同时 USB 需要外部 HSE 晶振。此时 CH340 串口不可用，调试需通过 SWD。

MPU6050 读取全是 0 或 I²C 扫描不到设备
  1. 确认 SCL/SDA 线上有 4.7 KΩ 上拉电阻到 3.3 V（部分模块已自带）。
  2. 检查 MPU6050 模块的 AD0 引脚电平——接 GND 时地址为 0x68，接 VCC 时为 0x69。
  3. 用万用表确认模块供电正常（VCC = 3.3 V）。
  4. 注意 F070F6 的 I2C1 引脚（PA9-SCL / PA10-SDA）与 CH340 串口共用 Pin 17/18，两者不能同时使用。可以改用软件 I²C（任意 GPIO 模拟）来避免冲突。
