VoidCore F1 – STM32F103T8U6

基于 STM32F103T8U6 的开发板

一块基于 STM32F103T8U6（Cortex-M3, 72 MHz）的极简小封装自制学习开发板。 USB Type-C 接口供电，原生 USB FS 免外挂串口芯片，板上只有必要元器件 — 没有按钮、没有多余 LED，所有 GPIO 全部引出给你。 经典 F103 生态 + 罕见的 VFQFPN-36 小封装，兼具丰富资料与紧凑体积。

定时器TIM1（高级，4通道互补PWM）、TIM2/TIM3（通用16-bit）、TIM4（通用16-bit）
特色原生 USB FS 免串口芯片、极简设计（无按钮无 LED）、PWR 指示灯、面包板适配排针
经典 F103 + 小封装

STM32F103 是全球出货量最大的 STM32 型号，拥有 最丰富的学习资料和社区生态。T8U6 是其中 VFQFPN-36 小封装版本，相比常见的 C8T6（LQFP-48）更紧凑：

  • 与 C8T6 完全相同的内核和外设，64 KB Flash + 20 KB RAM + 72 MHz
  • 原生 USB 2.0 FS — 可做 CDC 虚拟串口、HID 键盘鼠标、MSC U 盘等，无需外挂串口芯片
  • CAN 总线 — 工控/汽车电子入门
  • VFQFPN-36 封装仅 6×6 mm — 比 C8T6 的 LQFP-48（7×7 mm）更小，板子更紧凑
  • 大部分 GPIO 支持 5 V 容忍 — 可直接与 5 V 外设通信
  • 正点原子、野火、安富莱等全部 F103 教程均适用，代码仅需调整引脚映射

如果你已经用过 C8T6"蓝色药丸"，这块板子就是它的"黑色迷你版"。

2.2 引脚定义​

关于引脚编号

STM32F103T8U6 采用 VFQFPN-36 封装，共 36 个引脚（含底部散热焊盘 Pad 37）。 相比常见的 LQFP-48（C8T6），少了 PC13–PC15、PB8–PB15 等引脚，但核心外设（USB、USART、SPI、I²C、CAN、ADC）均完整保留。 Pin 2/3（OSC_IN/OSC_OUT）默认用于 8 MHz 晶振，可通过软件 Remap 为 PD0/PD1。

面包板排针（右侧）A0, BT0, B7, B6, B5, B4, B3, A15, A14, A13, RST, A10, +5V, VCC, GND引出至面包板；BT0 = BOOT0 引脚，需要进入 Bootloader 时用杜邦线短接到 VCC
本板无 BOOT0 按钮 — 如何进入 Bootloader

本板采用极简设计，未设置 BOOT0 按钮。BOOT0 引脚已通过排针（BT0）引出：

  1. 用杜邦线将右侧排针的 BT0 短接到 VCC（3.3V）。
  2. 重新插拔 Type-C 上电（或短接 RST 到 GND 再松开）。
  3. 芯片进入系统存储器 Bootloader 模式，可通过 USART1 ISP 或 USB DFU 烧录。
  4. 烧录完成后拔掉跳线，重新上电即恢复正常 Flash 启动。

日常开发使用 SWD 烧录无需操作 BOOT0，仅在芯片被锁死时才需要此操作。

PA11/PA12 与 USB/CAN 的引脚复用

PA11 和 PA12 同时承载 USB FS 和 CAN 两个外设的功能，二者不能同时使用。 本开发板默认将 PA11/PA12 连接至 Type-C 的 USB 数据线，因此使用 CAN 功能时需要外接 CAN 收发器并注意不要同时启用 USB。

4 快速上手​

你需要准备
  • USB Type-C 数据线 × 1（注意要数据线，不要只能充电的线）
  • SWD 调试器 × 1（ST-Link V2 / DAP-Link / J-Link 任选其一）
  • 杜邦线 若干（连接调试器与开发板）
  • 电脑（Windows / macOS / Linux）

4.1 安装开发环境​

  • STM32CubeIDE（推荐）
  • Keil MDK
  • PlatformIO + VS Code
  1. 前往 ST 官网 下载 STM32CubeIDE（免费，全平台支持）。
  2. 安装完成后首次启动，选择一个 Workspace 文件夹。
  3. 菜单 File → New → STM32 Project，在芯片选择器中搜索 STM32F103T8U6，选中后点击 Next。
  4. 填写项目名称，Targeted Language 选 C，Firmware Package 选最新版本，完成创建。
  5. ST-Link 驱动通常随 CubeIDE 自动安装。如果设备管理器识别不到，可手动安装 STSW-LINK009。
  1. 下载并安装 Keil MDK（Community 版免费，限制 32 KB 代码，F103T8 有 64 KB Flash 需注意）。
  2. 打开 Pack Installer，搜索 STM32F1，安装 Keil.STM32F1xx_DFP 包。
  3. 新建项目时 Device 选择 STM32F103T8Ux。
  4. 安装 ST-Link 驱动：STSW-LINK009。
  1. 安装 VS Code，在扩展商店搜索 PlatformIO IDE 并安装。
  2. 新建项目，Board 选择 genericSTM32F103T8（或 bluepill_f103c8 然后修改 board 配置），Framework 选 stm32cube。
  3. PlatformIO 会自动下载对应的 HAL 库和工具链。

4.2 接线​

只需要连接 3 根线（推荐 5 根）：

调试器 (ST-Link)          开发板 SWD 排针
─────────────            ──────────────
+5V   ────────────────── +5V  （可选，板子 Type-C 自带供电）
GND   ────────────────── GND
SWDIO ────────────────── DIO  (PA13)
SWCLK ────────────────── CLK  (PA14)
NRST  ────────────────── RST  （可选，支持调试器硬件复位）
注意事项
  1. 调试器输出电压可以使用 3.3 V 或者 5 V。
  2. 烧录时建议同时用 Type-C 数据线供电，调试器的电源仅作为信号参考，不建议单独作为板子电源。
  3. 如果连接了 RST，调试器可以自动复位芯片；未连接时在 IDE 中选择 Software Reset 即可。
  4. 禁止 ST-Link 在 +3.3 V 供电的同时接入 Type-C，可能会烧毁 ST-Link。
  5. 如果 SWD 连不上，可将排针上的 BT0（BOOT0）引脚用杜邦线短接到 VCC（3.3V），然后重新上电，即可进入 Bootloader 恢复 SWD 连接。

4.3 使用原生 USB（CDC 虚拟串口）​

本开发板无需外挂 CH340，通过 STM32 的原生 USB FS 即可实现虚拟串口功能：

  1. 在 CubeMX 中启用 USB → Device (FS)，Middleware 选择 USB_DEVICE → Communication Device Class (CDC)。
  2. 配置时钟树：HSE 8 MHz → PLL 倍频至 72 MHz，确保 USB 时钟为 48 MHz（通过 1.5 分频从 72 MHz 获得）。
  3. 编译烧录后，将 Type-C 数据线连接电脑，设备管理器中会出现 STMicroelectronics Virtual COM Port。
  4. 无需额外安装驱动（Windows 10/11 自带 CDC 驱动），即可使用串口工具通信。
USB CDC vs CH340

使用原生 USB CDC 的优势：省掉一颗 CH340 芯片 + 一颗晶振，BOM 更低、PCB 更小。 劣势：需要在固件中配置 USB 协议栈，对初学者略有门槛。如果只是需要简单的串口打印，可以先用 SWD 调试器自带的 SWO 功能或者 USART1（PA9/PA10）外接 USB-TTL 模块。

4.4 烧录验证​

  1. 用 Type-C 数据线连接开发板到电脑（PWR 红色 LED 亮起）。
  2. 用杜邦线按照上面的接线图连接 SWD 调试器。
  3. 打开 STM32CubeIDE / Keil，创建一个简单的 GPIO 点灯工程，编译烧录。
  4. 看到 LED 闪烁即表示环境搭建成功。

5 与 C8T6 "蓝色药丸"的对比​

STM32F103T8U6 与最常见的 STM32F103C8T6 实际上是同一个芯片 Die 的不同封装：

参数STM32F103T8U6（本板）STM32F103C8T6（蓝色药丸）
内核 / 主频Cortex-M3 / 72 MHzCortex-M3 / 72 MHz
Flash / RAM64 KB / 20 KB64 KB / 20 KB
封装VFQFPN-36（6×6 mm）LQFP-48（7×7 mm）
GPIO 数26 个37 个
USBFS（PA11/PA12）FS（PA11/PA12）
CAN1×1×
USART2×3×
SPI1×2×
I²C1×2×
ADC 通道10 个10 个
板子尺寸更小较大
选 T8U6 还是 C8T6？

如果你的项目 GPIO 需求不超过 26 个，T8U6 的板子更小、更紧凑，BOM 几乎相同。 如果你需要 SPI2、I2C2、USART3 或更多 GPIO（如驱动 TFT 屏），则应选择 C8T6 或更大封装。 所有 F103C8T6 的教程代码都可以直接用在 T8U6 上，只需注意检查引脚是否在 36pin 封装中可用。

6 常见问题​

烧录时提示 "No target connected" 或 "Error connecting to target"
  1. 检查 SWD 线（尤其 GND）是否接牢。
  2. 确认调试器驱动已安装——在设备管理器中应能看到 ST-Link 设备。
  3. 确认 Type-C 已插入且板子有供电（PWR 红灯应亮起）。
  4. 在 IDE 的调试器设置中尝试降低 SWD 频率（如从 4 MHz 降到 480 kHz）。
  5. 如果芯片之前被错误配置了 PA13/PA14 为 GPIO，用杜邦线将排针上的 BT0 引脚短接到 VCC（3.3V），重新上电进入 Bootloader，即可恢复 SWD 连接，重新擦除芯片。烧录完成后记得断开跳线。
USB CDC 虚拟串口在电脑上不识别
  1. 确认 CubeMX 中 USB 时钟配置正确——USB 需要精确的 48 MHz 时钟，必须使用 HSE（8 MHz 晶振）经 PLL 倍频，不能用 HSI。
  2. 检查 PA11（D−）和 PA12（D+）是否被其他功能占用。
  3. Windows 10/11 自带 CDC 驱动，通常无需手动安装；如果仍不识别，尝试安装 STM32 VCP 驱动。
  4. 确认 USB 数据线是双向数据线（非仅充电线）。
PA15、PB3、PB4 配置为 GPIO 后不工作

这三个引脚默认被 JTAG 调试接口占用（JTDI / JTDO / JTRST）。要将它们用作普通 GPIO，需要在代码中释放 JTAG 引脚：

__HAL_RCC_AFIO_CLK_ENABLE();
__HAL_AFIO_REMAP_SWJ_NOJTAG();  // 释放 PA15/PB3/PB4，保留 SWD

在 CubeMX 中，进入 SYS → Debug 设置为 Serial Wire（而非 JTAG），即可自动释放这三个引脚。

ADC 读数不准或一直为 0
  1. F103 的 ADC 在使用前必须执行校准（HAL_ADCEx_Calibration_Start()）。
  2. 确认引脚配置为模拟输入模式。
  3. ADC 时钟不能超过 14 MHz——在 CubeMX 的时钟树中检查 ADC 预分频器设置。
  4. 用万用表测量引脚实际电压，确认硬件连接正常。
如何判断 Type-C 线是数据线还是充电线？

插上电脑后如果设备管理器中没有出现任何新设备，而板子有供电（PWR 灯亮），说明可能是只能充电的线。换一根线试试——通常两头都有 USB 标志的更可能是数据线。

T8U6 和 C8T6 的代码能直接互换吗？

核心代码完全兼容，但需要注意：

  1. T8U6（VFQFPN-36）比 C8T6（LQFP-48）少了部分引脚，使用前检查目标引脚是否在 36pin 封装中存在。
  2. CubeMX 新建工程时选择正确的型号 STM32F103T8Ux，引脚映射会自动适配。
  3. 不在 T8U6 封装中的引脚（如 PB8–PB15、PC13–PC15）的代码需要注释或替换到其他可用引脚。
