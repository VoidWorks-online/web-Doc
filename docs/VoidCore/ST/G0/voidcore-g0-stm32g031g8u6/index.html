VoidCore G0 – STM32G031G8U6

基于 STM32G031G8U6 的开发板

一块基于 STM32G031G8U6（Cortex-M0+，64 MHz）的自制学习开发板。
Type-C 接口供电，板载 CH340N USB 转串口，并引出 SWCLK / SWDIO / RST / +5V / GND 五线 SWD 调试接口。
适合用于 STM32 基础外设、串口通信、I2C / SPI 总线和通用控制类项目的入门与练习。

1 特性一览​

特性说明
核心芯片STM32G031G8U6（Arm Cortex-M0+，64 MHz）
Flash / RAM64 KB / 8 KB
封装UFQFPN-28（4 × 4 mm）
供电方式USB Type-C（5 V），板载 3.3 V LDO
调试接口五线 SWD（SWCLK、SWDIO、RST、+5V、GND，支持 ST-Link / DAP-Link / J-Link）
板载串口CH340N USB 转 UART，免跳线直连 PC
可用 GPIO最多 26 个（含复用功能）
通信外设2× USART、1× LPUART、2× I2C、2× SPI/I2S
模拟外设12-bit ADC（15 个外部通道）
定时器TIM1、TIM2、TIM3、TIM14、TIM16、TIM17、LPTIM1/2、IWDG、WWDG、RTC
特色小尺寸封装、板载 CH340N、五线 SWD、适合通用型 STM32 入门
这块板适合做什么
  • 想学 STM32 基础外设：GPIO、定时器、PWM、ADC、UART
  • 想做总线通信练习：I2C 传感器、SPI Flash、串口协议
  • 想做体积较小的通用控制板：资源够用，上手门槛低
  • 想从 8 位单片机或 Arduino 过渡到 STM32：工具链和生态更完整

2.3 板载资源映射​

资源连接引脚备注
CH340N USB-UART TXPB6（USART1_TX）通过 CH340N 转 USB Type-C，连接电脑后可识别为串口设备
CH340N USB-UART RXPB7（USART1_RX）同上
SWDIOPA13五线 SWD 调试接口，调试专用
SWCLKPA14五线 SWD 调试接口，调试专用
RSTPin 5（NRST）五线 SWD 调试接口，支持调试器硬件复位
SWD +5V+5V五线 SWD 调试接口电源引出，来自 USB 5 V
SWD GNDGND五线 SWD 调试接口地
USB Type-C 5 V 输入—经板载 LDO 降压至 3.3 V 供给 MCU
调试与引脚复用注意事项
  • PA13 / PA14 默认用于 SWD 调试，开发早期不要轻易复用为普通 GPIO。
  • 如果连接了 RST，调试器在下载和调试时会更稳定。
  • 板载 CH340N 已占用 PB6 / PB7 作为串口收发引脚，如需改作其他功能，需要同步调整串口调试方案。

4 快速上手​

你需要准备
  • USB Type-C 数据线 × 1（注意要数据线，不要只能充电的线）
  • SWD 调试器 × 1（ST-Link V2 / DAP-Link / J-Link 任选其一）
  • 杜邦线 若干（连接调试器与开发板）
  • 电脑（Windows / macOS / Linux）

4.1 安装开发环境​

  • STM32CubeIDE（推荐）
  • Keil MDK
  • PlatformIO + VS Code
  1. 前往 ST 官网 下载 STM32CubeIDE。
  2. 安装完成后首次启动，选择一个 Workspace 文件夹。
  3. 菜单 File → New → STM32 Project，在芯片选择器中搜索 STM32G031G8U6。
  4. 填写项目名称，Targeted Language 选 C，选择对应固件包后完成创建。
  5. 如 ST-Link 未被系统识别，可补装 STSW-LINK009。
  1. 下载并安装 Keil MDK。
  2. 打开 Pack Installer，搜索 STM32G0，安装 Keil.STM32G0xx_DFP。
  3. 新建项目时 Device 选择 STM32G031G8Ux。
  4. 安装 ST-Link 驱动后即可下载调试。
  1. 安装 VS Code，在扩展商店搜索 PlatformIO IDE 并安装。
  2. 新建项目，Board 选择 genericSTM32G031G8，Framework 选 stm32cube。
  3. PlatformIO 会自动下载对应的 HAL 库和工具链。

4.2 接线​

本开发板引出了 SWCLK / SWDIO / RST / +5V / GND 五线 SWD 调试接口，推荐按下表连接：

调试器 (ST-Link)          开发板 SWD 接口
─────────────            ──────────────
+5V   ────────────────── +5V  （可选，板子 Type-C 自带供电）
GND   ────────────────── GND
SWDIO ────────────────── SWDIO (PA13)
SWCLK ────────────────── SWCLK (PA14)
NRST  ────────────────── RST   (NRST)
注意事项
  1. 调试器输出电压请与板上实际供电方案匹配。
  2. 烧录时建议同时接入开发板本身的 USB 供电。
  3. 如果连接了 RST，调试器可以自动复位芯片，调试稳定性通常更好。
  4. 开发早期不要轻易复用 PA13 / PA14，否则可能出现无法连接芯片的问题。
  5. 如果下载失败，可在 IDE 中尝试降低 SWD 频率，或使用 Connect Under Reset。

4.3 安装 CH340 驱动​

首次将 Type-C 线连接电脑后，系统需要识别板载 CH340N 芯片：

  • Windows
  • macOS
  • Linux

大多数 Windows 10/11 系统会自动安装驱动。如果设备管理器中出现黄色感叹号，手动下载安装：CH340 驱动（南京沁恒官网）。安装后在「设备管理器 → 端口」中看到 USB-SERIAL CH340 (COMx) 即为成功。

macOS 需要手动安装驱动：CH340 macOS 驱动。安装后可在终端执行 ls /dev/tty.wchusbserial* 确认设备是否出现。

Linux 内核自带 ch341 驱动，插入后执行 dmesg | tail 即可看到类似 /dev/ttyUSB0 的设备。如果权限不够，可执行：

sudo usermod -aG dialout $USER

然后重新登录。

4.4 烧录验证​

  1. 用 Type-C 数据线连接开发板到电脑。
  2. 用杜邦线将 SWD 调试器与开发板的 SWCLK / SWDIO / RST / GND 连接好，+5V 可按需连接。
  3. 在 STM32CubeIDE 或 Keil 中创建一个简单的 GPIO 点灯工程并编译下载。
  4. 如果程序能正常烧录并运行，即表示开发环境与调试连接正常。

随后可打开串口工具（推荐 Vofa+ 或 SSCOM），选择 CH340N 对应的串口号，波特率设置为 115200，验证串口通信是否正常。

5 常见问题​

烧录时提示 "No target connected" 或 "Error connecting to target"
  1. 检查 SWD 线和供电是否连接正常，尤其是 GND / SWDIO / SWCLK / RST。
  2. 确认调试器驱动已安装。
  3. 确认开发板已经正常上电，3.3 V 电压正常。
  4. 在 IDE 中尝试降低 SWD 频率或使用 Connect Under Reset。
  5. 如果之前误把 PA13 / PA14 配成普通 GPIO，可尝试在复位状态下重新连接并擦除程序。
串口没有输出或收到乱码
  1. 确认波特率两端一致，例如代码和串口工具都设置为 115200。
  2. 在设备管理器中确认 CH340 驱动正常，记下正确的串口号。
  3. 检查 USART1 和 GPIOB 时钟是否正确开启。
  4. 确认 PB6 / PB7 的复用功能配置正确，没有被其他外设占用。
ADC 读数不准或一直为 0
  1. 建议先执行 ADC 自校准。
  2. 确认引脚被配置为模拟输入模式，没有使能上下拉。
  3. 用万用表确认输入电压真实存在。
  4. 如涉及模拟量采样，建议检查采样时间设置是否合理。
如何判断 Type-C 线是数据线还是充电线？

插上电脑后如果开发板上电了，但系统没有识别出任何新设备，通常说明这根线可能只支持充电。换一根数据线再试。
