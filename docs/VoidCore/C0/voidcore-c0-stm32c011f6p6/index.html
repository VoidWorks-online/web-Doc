VoidCore C0 – STM32C011F6P6

基于 STM32C011F6P6 的开发板

一块基于 STM32C011F6P6（Cortex-M0+, 48 MHz）的极致低成本自制学习开发板。
USB Type-C 接口供电，板载 CH340N USB 转串口，引出 SWD 调试接口，插上线就能烧录。
芯片单价不到 2 元，内置 48 MHz RC 振荡器免外部晶振，是 用 32 位价格替代 8 位单片机的最佳选择。

1 特性一览​

特性说明
核心芯片STM32C011F6P6（Arm Cortex-M0+，48 MHz）
Flash / RAM32 KB / 6 KB
封装TSSOP-20（6.5 × 4.4 mm）
供电方式USB Type-C（5 V），板载 3.3 V LDO
调试接口SWD（支持 ST-Link / DAP-Link / J-Link）
板载串口CH340N USB 转 UART，免跳线直连 PC
可用 GPIO最多 18 个（含复用功能）
通信外设2× USART、1× I²C、1× SPI/I²S
模拟外设12-bit ADC 2.5 Msps（最多 13 个外部通道，TSSOP-20 实际可用 9 个）
定时器TIM1（高级，4通道互补PWM）、TIM3（通用16-bit）、TIM14/TIM16/TIM17（通用16-bit）
特色内置 48 MHz RC（±1%）免外部晶振、BOOT0 按钮、面包板适配排针、PWR 指示灯
极致低成本亮点

STM32C011F6P6 是 ST 推出的 C0 系列入门级 MCU，专为替代 8 位 / 16 位单片机而生：

  • 芯片单价不到 2 元（100 片批量），比许多 8 位 MCU 更便宜
  • 内置 48 MHz 高精度 RC（±1%），无需外部晶振即可全速运行，BOM 更精简
  • 与 STM32G0 引脚兼容，共享同一技术平台，可无缝升级到 G031/G071
  • 2.0 V ~ 3.6 V 宽电压供电，可直接使用两节干电池
  • 完整的 STM32 生态系统支持（CubeIDE / CubeMX / HAL / LL）

用 32 位 Cortex-M0+ 的性能，做 8 位单片机的价格 — 这就是 C0 系列的核心价值。

2.2 引脚定义​

关于引脚编号

STM32C011F6P6 采用 TSSOP-20 封装，共 20 个引脚。
该封装仅有一对供电引脚（VDD/VSS），硬件设计更为简洁。内置 48 MHz RC 振荡器，无需外接 HSE 晶振。
Pin 6（NRST）默认为复位功能，可通过修改 Option Byte 将其配置为通用 GPIO PF2，多出一个可用 I/O。

2.3 板载资源映射​

资源连接引脚备注
CH340N USB-UART TXPA9/PA0（USART1_TX）通过 CH340N 转 USB Type-C，连接电脑即出现 COM 口
CH340N USB-UART RXPA10/PA1（USART1_RX）同上
SWD_DIOPA13SWD 排针，调试专用

SWD_+5V+5VSWD 排针，来自 USB 5 V
BOOT0 按钮BOOT0默认下拉（Flash 启动）；按住按钮再上电/复位 = 进入系统存储器 Bootloader 模式
PWR 指示灯—红色 LED，上电即亮，指示 3.3 V 供电正常

面包板排针（顶部）GND, B6, A14, A13, A12, A11, A8, A7, A6, A5, A4引出至面包板
面包板排针（底部）+5V, VCC, GND, B7, C14, C15, RST/F2, A0, A1, A2, A3引出至面包板，RST/F2 为同一引脚（NRST 与 PF2 复用）
BOOT0 按钮使用说明
  • 正常使用时无需操作 BOOT0 按钮，默认从 Flash 启动。
  • 需要进入 Bootloader（ISP 烧录）时：按住 BOOT0 按钮不松手 → 按一下复位（或重新插入 Type-C 上电） → 松开 BOOT0，此时芯片进入系统存储器模式，可通过 USART 进行 ISP 烧录，SWD 调试也可正常使用。
  • 如果芯片被锁死（PA13/PA14 被误配为 GPIO），按上述步骤进入 Bootloader 后即可恢复 SWD 连接，重新擦除芯片。

4 快速上手​

你需要准备
  • USB Type-C 数据线 × 1（注意要数据线，不要只能充电的线）
  • SWD 调试器 × 1（ST-Link V2 / DAP-Link / J-Link 任选其一）
  • 杜邦线 若干（连接调试器与开发板）
  • 电脑（Windows / macOS / Linux）

4.1 安装开发环境​

  • STM32CubeIDE（推荐）
  • Keil MDK
  • PlatformIO + VS Code
  1. 前往 ST 官网 下载 STM32CubeIDE（免费，全平台支持）。
  2. 安装完成后首次启动，选择一个 Workspace 文件夹。
  3. 菜单 File → New → STM32 Project，在芯片选择器中搜索 STM32C011F6P6，选中后点击 Next。
  4. 填写项目名称，Targeted Language 选 C，Firmware Package 选最新版本，完成创建。
  5. ST-Link 驱动通常随 CubeIDE 自动安装。如果设备管理器识别不到，可手动安装 STSW-LINK009。
  1. 下载并安装 Keil MDK（Community 版免费，限制 32 KB 代码——刚好覆盖本芯片 Flash 容量）。
  2. 打开 Pack Installer，搜索 STM32C0，安装 Keil.STM32C0xx_DFP 包。
  3. 新建项目时 Device 选择 STM32C011F6Px。
  4. 安装 ST-Link 驱动：STSW-LINK009。
  1. 安装 VS Code，在扩展商店搜索 PlatformIO IDE 并安装。
  2. 新建项目，Board 选择 genericSTM32C011F6，Framework 选 stm32cube。
  3. PlatformIO 会自动下载对应的 HAL 库和工具链。

4.2 接线​

只需要连接 3 根线（推荐 5 根）：

调试器 (ST-Link)          开发板 SWD 排针
─────────────            ──────────────
+5V   ────────────────── +5V  （可选，板子 Type-C 自带供电）
GND   ────────────────── GND
SWDIO ────────────────── DIO  (PA13)
SWCLK ────────────────── CLK  (PA14)
NRST  ────────────────── RST  （可选，支持调试器硬件复位）
注意事项
  1. 调试器输出电压可以使用 3.3 V 或者 5 V。
  2. 烧录时需要同时用 Type-C 数据线供电（CH340N 需要 USB 5 V），调试器的 3.3 V 只是信号参考，不建议单独作为板子电源。
  3. 如果连接了 NRST，调试器可以自动复位芯片；未连接时在 IDE 中选择 Software Reset 即可。
  4. 禁止 ST-Link 在 +3.3 V 供电的同时接入 Type-C，可能会烧毁 ST-Link。
  5. 如果 SWD 连不上，尝试按住 BOOT0 按钮再上电进入 Bootloader 后重试。

4.3 安装 CH340 驱动​

首次将 Type-C 线连接电脑后，系统需要识别板载 CH340N 芯片：

  • Windows
  • macOS
  • Linux

大多数 Windows 10/11 系统会自动安装驱动。如果设备管理器中出现黄色感叹号，手动下载安装：CH340 驱动（南京沁恒官网）。安装后在「设备管理器 → 端口」中看到 USB-SERIAL CH340 (COMx) 即为成功。

macOS 需要手动安装驱动：CH340 macOS 驱动。安装后在终端执行 ls /dev/tty.wchusbserial* 确认设备出现。

Linux 内核自带 ch341 驱动，插入后执行 dmesg | tail 即可看到类似 /dev/ttyUSB0 的设备。如果权限不够，执行：

sudo usermod -aG dialout $USER

然后重新登录。

4.4 烧录验证​

  1. 用 Type-C 数据线连接开发板到电脑（PWR 红色 LED 亮起）。
  2. 用杜邦线按照上面的接线图连接 SWD 调试器。
  3. 打开 STM32CubeIDE / Keil，创建一个简单的 GPIO 点灯工程，编译烧录。
  4. 看到 LED 闪烁即表示环境搭建成功。

随后可打开串口工具（推荐 Vofa+ 或 SSCOM），选择 CH340N 对应的 COM 口，波特率 115200，验证串口通信是否正常。

5 与 8 位单片机的对比​

STM32C011F6P6 的核心定位是 替代传统 8 位 MCU，以下是与典型 8 位单片机的性能对比：

为什么选 C0 而不是 8 位？

价格几乎相同，但 C0 拥有 4 倍 Flash、6 倍 RAM、3 倍主频、更高精度 ADC、SWD 断点调试，以及完整的 STM32 生态系统。一旦学会 C0，后续可无缝升级到 G0 → G4 → F4 整条 STM32 产品线。

6 常见问题​

烧录时提示 "No target connected" 或 "Error connecting to target"
  1. 检查 SWD 线（尤其 GND）是否接牢。
  2. 确认调试器驱动已安装——在设备管理器中应能看到 ST-Link 设备。
  3. 确认 Type-C 已插入且板子有供电（PWR 红灯应亮起）。
  4. 在 IDE 的调试器设置中尝试降低 SWD 频率（如从 4 MHz 降到 480 kHz）。
  5. 如果芯片之前被错误配置了 PA13/PA14 为 GPIO，按住 BOOT0 按钮再上电进入 Bootloader，即可恢复 SWD 连接，重新擦除芯片。
串口没有输出 / 收到乱码
  1. 确认波特率两端一致——代码设置 115200，串口工具也要设为 115200。
  2. 在设备管理器中确认 CH340N 驱动正常，记下正确的 COM 口号。
  3. 乱码通常是时钟配置问题——STM32C011 默认使用内部 HSI48（48 MHz），确认 CubeMX 中系统时钟配置正确。
  4. 检查 USART 引脚映射与 AF 编号是否正确（C011 的引脚复用映射较灵活）。
ADC 读数不准或一直为 0
  1. 建议在 ADC 使用前执行自校准（HAL_ADCEx_Calibration_Start()）。
  2. 确认引脚配置为模拟输入模式，没有使能内部上拉/下拉。
  3. 用万用表测量引脚实际电压，确认硬件连接正常。
  4. C011 的 ADC 支持硬件过采样，如需更高精度可开启 oversampling 功能。
如何判断 Type-C 线是数据线还是充电线？

插上电脑后如果设备管理器中没有出现任何新设备（包括 CH340N），而板子有供电（PWR 灯亮），说明可能是只能充电的线。换一根线试试——通常两头都有 USB 标志的更可能是数据线。

C011 只有 6 KB RAM，够用吗？
  1. 对于大多数入门学习场景（GPIO、UART、ADC、SPI、I²C）完全够用。
  2. 避免定义大数组和大缓冲区——串口接收建议用 DMA + 环形缓冲区（几十字节即可）。
  3. 使用 LL 库替代 HAL 库可显著减少 RAM 占用。
  4. 如果确实需要更多 RAM，可以考虑升级到引脚兼容的 STM32G031F8P6（8 KB RAM + 64 KB Flash）。
C011 和 G031 是什么关系？可以互换吗？

STM32C011 和 STM32G031 共享同一技术平台，TSSOP-20 封装引脚兼容。C011 是 G031 的成本优化版本，主要区别在于 C011 主频略低（48 vs 64 MHz）、RAM 更小（6K vs 8K）、外设略少。两者的 HAL 库结构一致，代码迁移非常容易。
